# SE96K 驱动升级协议说明

本文说明上位机驱动如何与键盘固件配合，完成 **App 升级** 和 **Boot 升级**。
所有字节值均对照源码：

- Boot：`SE93T_BootLoader/SE93T_BootLoader`
- App：`SE96K_0026_GZS_400US_LINE_MONO/SE96K_0026_GZS_400US_LINE_MONO_claude`
- Updater：`SE96K_BootUpdater`（详见该目录 `README.md`）

---

## 1. 固件角色与 Flash 布局

| 固件 | 地址 | 作用 | 驱动如何识别 |
| --- | --- | --- | --- |
| Boot | 0x0000–0x0FFF | 接收固件、写 Flash | USB：VID 0x32C2 / PID 0x001B |
| 正式 App | 0x1000–0x7F7F | 键盘本身，可命令其跳 Boot | USB：VID 0x331A / PID 0x101D |
| Updater | 0x1000 起 | 一次性程序，改写 Boot 区后自动回到 Boot | 无 USB；bin 文件偏移 0x5FF8 为 `UPD` |

驱动只与 **App** 和 **Boot** 两种 USB 设备通信。Updater 对驱动而言是一个"特殊的固件文件"，
运行期间驱动只会看到 Boot 断开、随后重新枚举。

App 区内 0x7000–0x7FFF 为按键配置、灯效表和用户设置（0x7F00）。写入任何 bin（App 或 Updater）
都会覆盖该区域，**用户设置会恢复默认**，建议在界面上提示。

### 进入 Boot 的方式

| 方式 | 说明 |
| --- | --- |
| App 命令 | 驱动向 App 发 ISP 命令（见 3.2） |
| 组合键 | 按住 **左Ctrl + 左Win** 插上 USB |
| 无 App | 0x1000–0x1001 为 `FF FF`（空白）时上电自动停留在 Boot |

## 2. USB 通信方式

**App 和 Boot 的报文格式不同，这是最容易出错的地方。**

| | App | Boot |
| --- | --- | --- |
| HID 接口 | 接口 1（Windows 路径含 `mi_01`） | 接口 0（唯一接口） |
| Usage Page / Usage | 0xFF0F / 0x01 | 0xFF0E / 0x01 |
| Report ID | **0x0F** | **无** |
| 主机 → 设备 | EP0 SET_REPORT，32 字节（含 Report ID） | EP0 SET_REPORT，32 字节 |
| 设备 → 主机 | EP2 中断 IN，32 字节 | EP1 中断 IN，32 字节 |
| 命令头 | 0x0F（即 Report ID） | 0x0E（数据第 1 字节） |

两者都没有 OUT 端点。Windows 下用 `WriteFile` 或 `HidD_SetOutputReport` 下发，系统自动走 SET_REPORT。
缓冲区格式：

```
App 下发 (32 字节):  buf[0]=0x0F(ReportID)  buf[1]=命令  buf[2..31]=参数
Boot 下发(33 字节):  buf[0]=0x00(无ReportID) buf[1]=0x0E  buf[2]=命令  buf[3..32]=参数
```

读应答同理：App 读回 `buf[0]=0x0F`；Boot 读回 `buf[0]=0x00`，从 `buf[1]` 开始才是 `0E ...`。

> 下文统一采用固件内的编号：`out[n]` 为主机下发报文，`in[n]` 为设备应答，`[0]` 即命令头。

### 收发规则

- **一问一答**：每发一条命令就读一次应答，读到后再发下一条。固件只缓存一个待发应答，
  主机不读会导致后续应答被覆盖或卡住。
- 应答超时建议 500 ms，超时重发 1～2 次。
- 按 `in[1]` 判断应答属于哪条命令（App 会主动上报 MODE_INFO）。

## 3. App 侧命令

驱动升级只需要两条。

### 3.1 读版本 `MODE_INFO`（0x20）

```
out: 0F 20 00 00 00 00 00 00 00 00 00 ...      ← out[8]、out[10] 必须为 0
in : 0F 20 .. .. .. .. .. .. [8]灯效 .. [10]亮度/速度 .. .. ..
     [14..29] = fw_info: ID3 ID2 ID1 ID0 VER 02 00 01 'B''Y''K''C''-''V''1''0'
```

- 当前 App：项目ID `ID0..ID3 = 00 96 00 28`，版本 3。
- ⚠️ 本命令同时用于设置灯效：`out[8]` bit7 置 1 会改灯效，`out[10]` bit3 / bit7 置 1 会改亮度 / 速度。
  仅查询时这两个字节必须为 0。
- App 可能主动上报此应答（`bdevice_status_change`）。

### 3.2 跳 Boot `ISP`（0x1E）

```
out: 0F 1E 55 AA 00 FF 00 ...
in : 0F 1E 01
```

App 发出应答后：关 USB → 等 200 ms → 在 RAM 0x280 写 `3C C3 55 AA` → 软复位，Boot 见标志后留在 Boot。

- ⚠️ 发出后、**设备断开前不要再发任何命令**。App 在应答发出时会再次检查 `out[2..5]`，
  被新命令覆盖则不会跳转。
- 驱动随后等待 App 消失、Boot 出现，建议超时 5 s。

## 4. Boot 侧命令

所有应答 `in[0] = 0x0E`。

### 4.1 读 Boot 信息（0x20）

```
out: 0E 20
in : 0E 20 ID3 ID2 ID1 ID0 VER 00 96 00 09 01 'Y' 'i' 'Q'
```

| | in[2..5] | in[6] 版本 |
| --- | --- | --- |
| 旧 Boot | `01 FF 96 00` | 1 |
| 新 Boot | `28 00 96 00` | 2 |

驱动必须**两种都认**：判断是否本产品只比较 ID0/ID1 = `00 96`（即 `in[5]=00, in[4]=96`），新旧以 `in[6]` 区分。

### 4.2 写缓存 `W_FIFO`（0x11）

Boot 内部有 128 字节页缓存，分多包填入：

```
out: 0E 11 [2]偏移 [3]长度(≤28) [4..31]数据
in : 0E 11 [2]偏移 [3]长度 [4..]回读数据        ← in[3] bit7=1 表示失败
```

- 要求：长度 ≤ 28，偏移 + 长度 ≤ 128。
- 一页 128 字节分 5 包：28、28、28、28、16（偏移 0、28、56、84、112）。
- 建议逐字节比对回读数据。

### 4.3 写 Flash `W_FLASH`（0x10）

把缓存前 `len` 字节写入 Flash：

```
out: 0E 10 [2]地址低 [3]地址高 [4]len [5]0xA5 [6]校验低 [7]校验高
in : 0E 10 [2]地址低 [3]地址高 [4]len [5]ACK(1)/NAK(0) [6]- [7]错误码
```

- **地址**：相对 0x1000 的偏移，即 bin 文件偏移，范围 0x0000–0x6FFF。
- **len**：偶数且 ≤ 128。新 Boot 还要求不跨页：`(地址 & 0x7F) + len ≤ 128`。
  **驱动统一 128 字节对齐整页写**，新旧 Boot 都兼容。
- **out[5]**：Boot 只要求 ≤ 0xA5，固定填 0xA5。
- **校验**：

  ```c
  uint16_t cs = 0xFA21;
  for (int i = 0; i < len; i += 2)
      cs += page[i] | (page[i + 1] << 8);   /* 16 位小端字累加 */
  out[6] = cs & 0xFF;
  out[7] = cs >> 8;
  ```

- **错误码 in[7]**：1 长度错、2 校验错、3 地址错、4 写后回读不一致。
- 页内容与 Flash 现有内容一致时不擦写，直接回 ACK。
- 一页擦写约 5 ms（擦 3 ms + 写 2 ms），写完才应答。

### 4.4 读 Flash `R_FLASH`（0x12，可选校验）

```
out: 0E 12 [2..3]地址 [4..5]长度
in : 连续多包，每包: 0E 12 [2..3]本包偏移 [4..31]28 字节数据
```

⚠️ Boot 每包最多等约 20 ms，主机未取走即放弃整个读取。**驱动必须持续挂读请求**；长度取偶数。

### 4.5 运行 App `APP`（0x1E）

```
out: 0E 1E
in : 0E 1E [2]ACK(1)/NAK(0)
```

- 0x1000 处非空白才回 ACK，随后复位运行 0x1000 处程序（正式 App 或 Updater）。
- 旧 Boot：5 ms 后复位；新 Boot：关 USB → 200 ms → 复位，主机能看到一次干净的拔出。

## 5. 固件文件检查

bin 文件固定 **0x6F80（28544）字节**，对应 0x1000–0x7F7F。偏移 0x5FF0 处 16 字节为固件标识：

| bin 偏移 | 正式 App.bin | Updater.bin |
| --- | --- | --- |
| 0x5FF0–0x5FF3 | 项目ID ID3 ID2 ID1 ID0（`28 00 96 00`） | 新 Boot 的项目ID（同上顺序） |
| 0x5FF4 | App 版本号 | **将写入的新 Boot 版本号**（下文 `NEW_BOOT_VER`） |
| 0x5FF5–0x5FF7 | `02 00 01` | `00 00 00` |
| 0x5FF8–0x5FFF | `BYKC-V10` | **`UPD-BOOT`** |

驱动应：

1. 校验文件大小。
2. `0x5FF8..0x5FFA == "UPD"` → 按 Boot 升级流程（6.2）；否则按 App 升级流程（6.1）。
   App 流程中若选中的是 Updater，必须拒绝（否则键盘停在 Boot，看起来像"变砖"）。
3. 项目ID 的 ID0/ID1（偏移 0x5FF3、0x5FF2 = `00 96`）与设备不符时拒绝。
   Boot 不检查项目ID，只能由驱动把关。

## 6. 升级流程

### 写入顺序：首页最后写（App 与 Updater 通用）

Boot 仅凭 0x1000 开头两字节判断"是否有 App"。若从低地址往高写、中途掉电，
上电会跳进不完整的程序，只能靠组合键恢复。因此：

```
1. 偏移 0x0000 这一页写成全 0xFF       → Boot 视为"无 App"，掉电后上电自动停在 Boot
2. 依次写偏移 0x0080 ~ 0x6F00 各页
3. 最后写偏移 0x0000 页的真实数据
4. (可选) R_FLASH 回读全片比对
```

每页的写法：W_FIFO ×5（填满 128 字节）→ W_FLASH（len = 128）。现有 Boot 无需修改即支持该顺序。

### 6.1 升级 App

```
[App ] MODE_INFO → 检查 bin 项目ID 与设备一致（第 5 节）
[App ] ISP 0F 1E 55 AA 00 FF → 等 App 断开 → 等 Boot 枚举（≤5 s）
[Boot] 0x20 读信息，确认 ID0/ID1 = 00 96
[Boot] 按"首页最后写"写入 App.bin
[Boot] APP 0x1E → 等 Boot 断开 → 等 App 枚举 → MODE_INFO 确认新版本
```

设备已在 Boot（组合键或无 App）时，从第 3 步开始。

### 6.2 升级 Boot（通过 Updater）

```
 1. [App ] ISP → 等 Boot 枚举
 2. [Boot] 0x20 读信息 → 若 in[6] == NEW_BOOT_VER，跳到第 7 步
 3. [Boot] 按"首页最后写"写入 Updater.bin
 4. [Boot] APP 0x1E → Boot 断开
 5. Updater 运行约 0.2 s，改写 Boot 区，软复位进入新 Boot（驱动此时看不到设备）
 6. 等 Boot 重新枚举（≤5 s）→ 0x20 读信息 → in[6] == NEW_BOOT_VER 才算成功
 7. [Boot] 按"首页最后写"写入正式 App.bin
 8. [Boot] APP 0x1E → 等 App 枚举 → MODE_INFO 确认
```

`NEW_BOOT_VER` 取自 Updater.bin 偏移 0x5FF4，驱动无需写死。

前提：芯片烧录选项"0000-0FFF 写保护"为"允许擦写"。否则 Updater 写第 0 页失败后停机，
只能用烧录器恢复。**量产前务必用样机验证。**

## 7. 异常处理

| 现象 | 原因 | 驱动处理 |
| --- | --- | --- |
| ISP 后 5 s 内 Boot 未出现 | App 未收到命令，或断开前又发了命令 | 重新查找 App 再发一次；仍失败则提示用户按住 左Ctrl+左Win 插线 |
| W_FIFO 应答 in[3] bit7=1 或回读不符 | 参数越界或传输错误 | 重发该包 |
| W_FLASH NAK，错误码 2 | 缓存与校验不一致 | 重发整页（W_FIFO×5 + W_FLASH），最多 3 次 |
| W_FLASH NAK，错误码 4 | 写后回读不一致 | 重试；连续失败则中止，提示硬件问题 |
| APP 命令回 NAK | 0x1000 为空白 | 说明 App 未写入，重新执行写入流程 |
| Boot 升级第 6 步超时 | Updater 写入失败停机（多为 Boot 区写保护） | 提示用户重新插拔；上电后 Updater 自动断点续写，驱动回到第 6 步等待 |
| 第 6 步枚举成功但版本未变 | Updater 判定非本产品 Boot 或镜像校验失败，未改动 Boot | 报"Boot 更新失败"，继续第 7 步写回 App，键盘可正常使用 |
| 写入中途断开 | 掉电或拔线 | 因"首页最后写"，重新插上会停在 Boot，从头再写即可 |
| 上电直接进入 Boot | 0x1000 空白或按了组合键 | 正常，进入写 App 流程 |

## 8. 命令速查

| 设备 | 命令 | 下发 | 应答要点 |
| --- | --- | --- | --- |
| App | 读版本 | `0F 20 00…`（out[8]=out[10]=0） | `in[14..29]` = fw_info |
| App | 跳 Boot | `0F 1E 55 AA 00 FF` | `0F 1E 01`，随后断开 |
| Boot | 读信息 | `0E 20` | `in[2..5]` 项目ID，`in[6]` 版本 |
| Boot | 写缓存 | `0E 11 偏移 长度 数据…` | `in[3]` bit7=1 失败 |
| Boot | 写 Flash | `0E 10 地址L 地址H len A5 csL csH` | `in[5]` ACK/NAK，`in[7]` 错误码 |
| Boot | 读 Flash | `0E 12 地址L 地址H 长度L 长度H` | 多包，每包 28 字节 |
| Boot | 运行 App | `0E 1E` | `in[2]` ACK/NAK，随后断开 |
